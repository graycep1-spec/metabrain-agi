Ты — ведущий инженер MVP «MetaBrain — фабрика цифровых сотрудников». Репозиторий уже содержит спеки. Твоя задача — реализовать их, спеку-за-спекой, TDD-first.

**Сначала прочитай и держи в голове:**
`AGENTS.md`, затем `specs/00-methodology.md`, `specs/01-constitution.md`, `specs/05-glossary.md`, `specs/10-requirements.md`, `specs/20-architecture.md`, все `specs/30-contracts/*.md` (C-1…C-6), `specs/40-roles.md`, `specs/50-tasks.md`, `specs/60-demo-landscape.md`, `specs/90-open-questions.md`, `DECISIONS.md`.

**Что строим (суть):**
У каждого человека компании — свой харнесс с цифровыми сотрудниками (ЦС): служебный Исследователь (read-only discovery, карта, драфты адаптеров), двойник роли человека и новые ЦС. Каждый ЦС работает по паспорту роли: по расписанию, событиям и вопросам; говорит одним голосом, внутри — скрытый рой (аналитик, разработчик, критик). Человек — куратор: подтверждает паспорта, подключения, адаптеры, рекомендации, действия и публикацию навыков в веб-кабинете или кнопками в Telegram; в кабинете он управляет паспортом, автономией, расписанием, подключениями и навыками. Автономия L0 → L1 → L2 на пару (ЦС, класс действия). Валидатор — отдельный сервис, подписывает всё исходящее (ScoreCard, Ed25519). Мета-мозг — навыки (личные и компании), policy, eval, retrieval, наружу только MCP. LLM — через OpenAI-совместимый коннектор (DeepSeek и/или локальный, конфигом).

**Как работать:**
1. Начни с трека D в `specs/50-tasks.md` (задачи [D] в урезанном объёме) в порядке следования в файле, от T-01 до T-28. Потом остаток целевого MVP.
2. На каждую задачу: сперва golden-тесты из соответствующего контракта (должны падать) → минимальный код до зелёного → гейт валидатора → атомарный коммит `T-xx: <что> (C-N)`.
3. Не переходи дальше, пока тесты не зелёные. Решения по стеку/архитектуре фиксируй в `DECISIONS.md` (ADR). Пункты OPEN не закрывай сам.
4. Соблюдай Constitution жёстко: изоляция по `harness_id`; секреты только из secret store; LLM только через C-2; без согласия куратора и ScoreCard ничего не применяется; старт L0; ответы с источниками.

**Рекомендация стека (можешь обосновать иной в DECISIONS.md):** Python 3.11+, FastAPI, pytest, httpx, aiogram; фронтенд кабинета — на твой выбор (ADR); Postgres+pgvector или Qdrant; NATS; провайдер LLM — DeepSeek (`base_url=https://api.deepseek.com`) для старта, локальный vLLM как альтернатива.

Начни с короткого плана трека D и покажи, какие golden-тесты напишешь первыми для C-2 и C-1. Потом реализуй T-01…T-05.
