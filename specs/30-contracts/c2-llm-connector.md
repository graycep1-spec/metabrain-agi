# C-2 · LLM-коннектор (OpenAI-совместимый, вкл. внешний DeepSeek)

Единый интерфейс к любой OpenAI-совместимой модели; смена провайдера — конфигом, без изменения агентов (R-06).

```
chat.completions(request) -> response        # OpenAI /v1/chat/completions-совместимо
embeddings(request) -> vectors               # OpenAI /v1/embeddings-совместимо
```

Конфиг провайдера (из роутера, значения — из env/secret store):
```
{ name, base_url, api_key_ref, model, family, max_tokens, temperature }
```
Примеры: DeepSeek (`base_url=https://api.deepseek.com`, модели `deepseek-flash` и `deepseek-v4-pro`; имена `deepseek-chat`/`deepseek-reasoner` выведены DeepSeek из обращения 24.07.2026), локальный vLLM (`base_url=http://vllm:8000/v1`).

Контекст вызова (передаётся агентом, обязателен):
```
{ company_id, harness_id, employee_id, job_id, sub_role: analyst | developer | critic | researcher }
```

Правила:
- Роутер выбирает провайдера по `sub_role` из policy (C-5 `policy.get`); критик — другое `family`, чем разработчик.
- **Перед egress во внешний провайдер — DLP-фильтр** (R-07): правила разметки чувствительных полей берутся из policy; помеченные поля не отправляются или маскируются. Разметку ставят адаптеры при `probe` (поле `sensitivity` в Facts, C-3).
- **Данные ландшафта попадают в промпт только через коннектор.** Агент не вставляет значения Facts в текст сообщений сам. Он передаёт `request.facts[]` (Facts из C-3) и ссылается на них в сообщениях плейсхолдерами `{{fact:<ref>.<field>}}`. Коннектор применяет DLP к `facts` по их `sensitivity`, затем подставляет значения: замаскированное поле → `[REDACTED:<label>]`, удалённое → плейсхолдер убирается. Плейсхолдер на несуществующий факт → ошибка до вызова.
- Для внешнего провайдера DLP выключить нельзя: `DLP_ENABLED=false` при `external=true` → ошибка старта. Флаг действует только для локального провайдера.
- `field_sensitivity` и другие служебные поля запроса провайдеру не отправляются никогда.
- Каждый вызов: provenance (провайдер, модель, токены, стоимость, латентность) → телеметрия и журнал на `harness_id` и `employee_id` (C-009).
- Лимит бюджета/токенов из policy проверяется **до** вызова; превышение → отказ `budget_exceeded` с указанием лимита (R-12). Правила `budget_guard`:
  - стоимость вызова = `prompt_tokens × input_cache_miss + completion_tokens × output` по `policy.pricing` (цены за 1M, пиковый тариф): учтённая сумма не меньше реального счёта;
  - провайдер без цены в `policy.pricing` → отказ до вызова (стоимость нельзя посчитать);
  - до вызова для каждого лимита: потрачено + верхняя оценка вызова (`max_tokens × output`) ≤ лимит, иначе отказ; проверяются `budget_usd_total.installation` (все харнессы установки), `budget_usd_per_day.harness` и `.employee`, `tokens_per_day.harness` и `.employee`; сутки — по UTC;
  - в отказе: какой лимит, его значение и остаток.
- `api_key` только из secret store; никогда в репо/промтах/логах.

Golden: GT-c2-01..06 (подмена base_url; DLP режет помеченное поле; стоимость пишется на харнесс и ЦС; ключ не утекает в лог; критик и разработчик получают разные `family`; превышение бюджета → отказ). GT-c2-09 — при потраченных 4,99 $ из `budget_usd_total.installation = 5` вызов с верхней оценкой > 0,01 $ отклонён до обращения к провайдеру, в любом харнессе установки.
Дополнительно: GT-c2-07 — значение PII-поля из `facts`, на которое ссылается плейсхолдер в `content`, не появляется в теле HTTP-запроса к внешнему провайдеру (проверка по сырому телу); GT-c2-08 — `DLP_ENABLED=false` с внешним провайдером → ошибка старта; служебные поля отсутствуют в теле запроса.
