# Глоссарий

Термины ниже обязательны для всех спек, кода и тестов. Если в тексте слово употреблено в другом смысле — это ошибка спеки.

| Термин | Определение |
|---|---|
| **Компания** | Тенант. Объединяет харнессы людей одной организации и общую библиотеку навыков компании. Данные разных компаний не пересекаются никогда. |
| **Человек** | Сотрудник компании, зарегистрированный через канал (Telegram). У человека ровно один харнесс. В старых текстах — «пользователь». |
| **Веб-кабинет** | Веб-интерфейс человека для управления своими ЦС: паспорт, автономия, предложения, журнал, подключения, навыки, расписание. Вход — через Telegram (C-1). |
| **Харнесс** | Изолированный контур человека: его цифровые сотрудники, подключения к системам, память, карта ландшафта, журнал. Другие люди, в том числе из той же компании, данных харнесса не видят. |
| **Цифровой сотрудник (ЦС)** | Агент с паспортом роли, памятью, инструментами и уровнем автономии. Работает постоянно: по расписанию, по событиям и по вопросу человека. Виды: двойник, новый. |
| **Двойник** | ЦС, чей паспорт роли повторяет обязанности и цели роли владельца харнесса. В MVP двойник **не** имитирует стиль и решения человека (OPEN-02). |
| **Новый сотрудник** | ЦС на роль, которой у владельца харнесса нет. Нанимается владельцем по паспорту роли. |
| **Паспорт роли** | Машиночитаемое описание ЦС (C-6): обязанности, цели и метрики, границы решений, эскалации, инструменты, триггеры, уровни автономии. |
| **Куратор** | Человек, отвечающий за ЦС: подтверждает или возвращает предложения, выдаёт согласия, меняет автономию. В MVP куратор = владелец харнесса. |
| **Исследователь** | Служебный ЦС харнесса. Ведёт read-only discovery подключённых систем, строит карту ландшафта, драфтит адаптеры. Есть в каждом харнессе, вручную не создаётся. |
| **Скрытый рой** | Внутренние суб-роли каждого ЦС: аналитик, разработчик, критик. Человек их не видит. |
| **Ландшафт** | Подключённые к харнессу системы и их объекты. |
| **Адаптер** | Код интеграции с системой ландшафта (C-3). |
| **Класс действия** | Именованный тип записи в систему, объявленный адаптером (напр. `task.update_status`). Единица, на которую выдаётся автономия. |
| **Предложение** | То, что ждёт решения куратора. Виды: `passport`, `recommendation`, `action`, `adapter`, `skill_publish`, `autonomy_change`, `connect`. |
| **Согласие (`consent_token`)** | Одноразовый подписанный токен. Выпускается только по явному действию куратора в канале; привязан к харнессу, предмету и scope; имеет срок действия (C-1). |
| **Уровень автономии** | **L0** — анализ и рекомендации, записи нет. **L1** — запись после подтверждения куратором каждого действия. **L2** — запись в пределах политики без подтверждения каждого действия, с пост-проверкой и уведомлением куратора. Задаётся на пару (ЦС, класс действия). |
| **Инцидент** | Провал пост-проверки действия, отметка куратора «инцидент» или срабатывание security-чекера на исполненном действии. |
| **Работа (job)** | Один запуск ЦС по триггеру (`schedule`, `event`, `ask`) с сохраняемым состоянием (C-6). |
| **Навык** | Дистиллированный опыт: версионированный неизменяемый артефакт (C-5). **Личный** — виден только в харнессе автора. **Навык компании** — опубликован через гейт и виден всем харнессам компании. |
| **ScoreCard** | Подписанный вердикт валидатора по артефакту (C-4). `score_ref` = `scorecard_id`. |
| **Журнал** | Неизменяемая лента событий харнесса: решения куратора, работы, действия, вызовы адаптеров, вызовы LLM (C-008, C-009). |
