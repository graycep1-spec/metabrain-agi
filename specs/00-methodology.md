# Методология (xDD)

Уровни спецификаций: **требования** (бизнес-операции) → **формальная** (функциональные блоки) → **контракты на границе** → дизайн (КАК; не спецификация).

Два критерия любой спеки:
1. **Верифицируемость** — по документу строится проверка «соответствует / нет».
2. **Предмет с границей** — специфицируем наблюдаемое снаружи интерфейса. Фичи не специфицируем — специфицируем модули, контракты, форматы, протоколы.

- **SDD:** спеки версионируются в git, они — source of truth.
- **DDD:** bounded contexts — Harness, Validator, Metabrain, Landscape, LLM. Коннекторы и адаптеры — anti-corruption layer.
- **TDD (red-green):** для каждого контракта — golden-набор (валидные/невалидные примеры); контрактные тесты пишутся **до** реализации и живут в CI. Сначала красный тест, потом код до зелёного.

Порядок работы кодинг-агента: прочитать спеки → написать контрактные тесты из golden → реализовать до зелёного → гейт валидатора → коммит.
