# Уровень задач — план сборки (TDD-first)

Каждая задача: сначала golden-тесты из контракта (красные) → код до зелёного → гейт валидатора → атомарный коммит `T-xx: <что> (C-N)`. Задачи ≤ ~0.5–1 дня.

Два трека:
- **Трек D — демо 48 ч.** Вертикальный срез на L0. Задачи отмечены **[D]**; в треке D они делаются в урезанном объёме, указанном в скобках. Идти первым.
- **Целевой MVP M0–M8** — все задачи в полном объёме.

## Сценарий демо (Definition of Done трека D)

Процесс — обработка заявок и заказов (`60-demo-landscape.md`).

1. Менеджер A регистрируется в Telegram и создаёт компанию, менеджер B входит по инвайту A.
2. A пишет `/role` с описанием своей роли менеджера по продажам → входит в веб-кабинет через Telegram → видит черновик паспорта двойника, правит расписание → подтверждает в кабинете.
3. A подключает `demo-landscape` (read-only, согласие) → Исследователь драфтит адаптер → валидатор → согласие → карта: `crm`, `stock`, `pricing`.
4. Двойник A при обходе по расписанию находит заявку 1, видит нехватку позиции и присылает черновик КП с аналогом. В КП есть источники, маржа ≥ `min_margin`.
5. A подтверждает рекомендацию и правило про аналог → решение в журнале → кандидат навыка → профиль Skill → A соглашается опубликовать навык в компанию.
6. Двойник B разбирает заявку 2 с навыком компании: `skill_id@version` в трейсе и `sources[]`, вопроса куратору про аналог нет.
7. В журнале кабинета A видна вся цепочка: паспорт → подключение → отчёт с источниками → решение → публикация навыка.

## M9 · Поставка
- T-36 Лендинг MetaBrain: инструкция для пользователей и дистрибутивы для Linux, macOS и Windows.
  - Страница: что такое MetaBrain и для кого (по `15-customer-journey.md`); что нужно заранее — Docker, ключ DeepSeek, отдельный бот в BotFather, домен с HTTPS для входа в кабинет; установка; первые шаги (сценарий демо); частые проблемы (из `DEMO.md`).
  - Дистрибутивы на каждый релиз: `metabrain-<версия>.tar.gz` (Linux, macOS) и `metabrain-<версия>.zip` (Windows) с `install.sh` / `install.ps1` и файлом `SHA256SUMS`. Собирает CI по тегу `v*`.
  - Команды из оболочек. Загрузчик скачивает релиз, сверяет SHA-256, распаковывает и запускает установщик:
    - Linux и macOS (bash, zsh): `curl -fsSL https://<лендинг>/get.sh | bash` и рядом — вариант «скачать → проверить → запустить» без передачи скрипта в shell;
    - Windows (PowerShell): `irm https://<лендинг>/get.ps1 | iex` и тот же вариант с проверкой;
    - для команды разработки: `git clone` репозитория и `./install.sh` (или `.\install.ps1`) из рабочей копии.
  - macOS: `install.sh` распознаёт Darwin — ставит в `~/metabrain` (Docker Desktop монтирует только домашние папки), без `--domain`.
  - Готово, когда: на чистых Linux-VM, Mac и Windows с Docker Desktop одна команда со страницы ставит MetaBrain, и кабинет отвечает на `/healthz`; подменённый архив не проходит проверку SHA-256; на странице нет секретов и внутренних адресов.
  - Перед началом решить OPEN-18: кто может скачивать и где живут страница и архивы.

- T-37 Модуль самосовершенствования (ADR-029): саброль `debugger` читает телеметрию харнесса (журнал, расход), драфтит улучшение (адаптер/навык/паспорт) → валидатор → предложение куратору → согласие. Без автономной самоправки и без изменения кода сервиса. Предложение вида `self_improvement`; GT — упавшая работа/повтор `answer.blocked` → драфт-предложение, применение только после согласия.
