# AGENTS.md — правила для кодинг-агента (DeepSeek-сессия)

Ты строишь MVP по спекам. Работай спеку-за-спекой, TDD-first. Не выдумывай требования — если чего-то нет, спроси или пометь `OPEN:` и продолжай по остальному. Пункты из `specs/90-open-questions.md` не закрывай своими решениями: делай точку расширения и ссылку `OPEN-xx` в коде.

## Порядок работы
1. Прочитай `specs/` по порядку: `00-methodology` → `01-constitution` → `05-glossary` → `10-requirements` → `20-architecture` → `30-contracts/*` (C-1…C-6) → `40-roles` → `50-tasks` → `60-demo-landscape` → `90-open-questions`.
2. Сначала трек D (задачи с пометкой [D] в урезанном объёме, в порядке следования в файле), затем целевой MVP: M0 → M2 → M2w → M3 … M8.
3. На каждую задачу: напиши golden-тесты из контракта (красные) → код до зелёного → прогони гейт валидатора → коммит с ссылкой на T-xx и контракт.
4. Не переходи к следующей задаче, пока текущие тесты не зелёные.

## Незыблемое (из Constitution)
- Спеки — source of truth; расходишься со спекой — меняй спеку отдельным коммитом и обоснуй.
- Харнесс на человека: каждый запрос к данным фильтруется по `harness_id` на уровне хранилища.
- Секреты только из secret store; никогда в коде, промтах, логах, коммитах.
- LLM — через коннектор C-2; не хардкодь провайдера; DeepSeek и локальный — конфигом.
- ЦС не выдаёт себе доступ, не меняет свой паспорт и автономию; всё применяется только после согласия куратора и подписи валидатора.
- Старт L0 (read-only); запись — только на L1/L2, включённом куратором для пары (ЦС, класс действия).
- Каждый ответ — с источниками; наружу без ScoreCard ничего не идёт.
- Опыт уходит из харнесса только навыком через профиль Skill и согласие автора.

## Стиль
- Язык/стек — на твой выбор в рамках `docker compose` (рекомендация: Python 3.11+, FastAPI, pytest; pgvector/qdrant; nats; aiogram для Telegram; фронтенд веб-кабинета — обоснуй в ADR). Обоснуй выбор в `DECISIONS.md`.
- Малые модули по bounded contexts (Channel/Harness/Workforce/Validator/Metabrain/Landscape/LLM); между ними — только контракты.
- Коммиты атомарные, сообщение: `T-xx: <что> (C-N)`.

## Гейты
- CI: линт + все тесты зелёные.
- Перед мержем фичи, меняющей исходящее поведение, — прогон профиля валидатора на golden.

Решения фиксируй в `DECISIONS.md` (ADR-стиль: контекст → решение → последствия → источник).
