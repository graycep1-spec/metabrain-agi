# Демо: как поднять и провести

Сценарий — шаги 1–7 из `specs/50-tasks.md`: два менеджера одной компании, двойник A готовит КП по заявке 1042, его правило про аналог становится навыком компании, двойник B применяет навык к заявке 1043.

## Что нужно заранее

- Linux VPS с Docker Engine и Compose, домен с HTTPS для кабинета (reverse proxy на порт 8081).
- Telegram-бот: в BotFather — токен и username; там же **Login Widget**: Allowed URL `<WEB_BASE_URL>/auth/callback`, взять Client ID и Client Secret.
- Ключ DeepSeek. Политика ограничивает расход: 5 $ на установку, 0,5 $ в день на сотрудника, 1 $ в день на харнесс (ADR-021). Прогон двойника (аналитик + критик) стоит порядка 0,5–1 цента.

## Поднять

На сервере, где будет кабинет (нужны Docker и, для HTTPS, nginx с certbot):

```bash
sudo ./install.sh --domain <домен кабинета> --email <почта для Let's Encrypt>
```

Установщик сам сгенерирует ключи подписи, пароли и токены менеджеров, скрыто спросит ключ DeepSeek, токен отдельного бота и Client ID/Secret входа через Telegram, поднимет сервисы и проверит ключ и бота. Ключ DeepSeek уже есть в env-файле другого сервиса на этом сервере — `--deepseek-key-from <файл>` перенесёт его, не показывая.

После установки: в BotFather → бот → Login Widget добавить Allowed URL `https://<домен>/auth/callback`. Токены менеджеров `manager-a` и `manager-b` для шага 3 — `sudo /opt/metabrain/install.sh tokens`.

## Провести

**1. Регистрация.** A пишет боту `/start` → «Согласен». В ответе — ссылка-приглашение; B открывает её → «Согласен».

**2. Паспорт двойника.** A пишет `/role Я менеджер по продажам, готовлю КП по новым заявкам`. Затем входит в кабинет («Войти через Telegram») → «Сотрудники» → двойник → «Изменить черновик», в расписании ставит `*/15 * * * * | 1` (время в UTC) → «Предложения» → «Подтвердить».

**3. Подключение.** A пишет `/connect crm`, открывает ссылку из ответа, вводит токен `manager-a` → «Предложения»: подтвердить подключение; сразу появится адаптер, проверенный валидатором, — подтвердить. То же для `stock` и `pricing`. В конце одно предложение «Дать доступ…» со всеми тремя системами — подтвердить. «Подключения» → карта: заявки, склад, цены и связи между ними.

**4. Отчёт по расписанию.** В ближайший слот (до 15 минут плюс до 30 секунд) двойник присылает A в Telegram разбор заявки 1042: позиции A-17 не хватает, предлагается аналог A-17M, у каждого утверждения — источник. В «Предложениях» — рекомендация. Не хочется ждать — A спрашивает бота: «Что с заявкой 1042?»; ответ идёт тем же путём.

**5. Навык.** A подтверждает рекомендацию → появляется предложение «Навык в компанию» → подтвердить. «Навыки» → навык компании «с согласия автора».

**6. Двойник B.** B пишет `/role …` и подтверждает кнопкой в боте, входит в кабинет, подключает `crm`, `stock`, `pricing` токеном `manager-b`, подтверждает. Затем спрашивает бота: «Что с заявкой 1043?» — в ответе аналог D-09S и источник «навык «…»».

**7. Журнал.** Кабинет A → «Журнал», фильтры по очереди: «Паспорт действует», «Система подключена», «Отчёт сотрудника», «Решение куратора», «Навык опубликован».

После демо поставьте двойников на паузу (карточка сотрудника) или смените расписание на редкое — иначе расписание продолжит тратить бюджет.

## Если что-то не так

| Симптом | Причина |
|---|---|
| Форма доступа: «Хранилище доступов не настроено» | пустой `SECRET_STORE_KEY` |
| Вход в кабинет отвечает «недоступен» (503) | нет `TELEGRAM_OIDC_CLIENT_ID`/`_SECRET` или `WEB_BASE_URL` |
| «Навыки недоступны» | мета-мозг не поднят: `docker compose logs metabrain` |
| Навык компании не публикуется, в журнале «Навык не создан» | `CONSENT_PUBLIC_KEY` не от того `CONSENT_SIGNING_KEY` — сгенерируйте `.env` заново |
| Бот отвечает про бюджет (429) | исчерпан лимит 5 $ или дневной лимит сотрудника |
| Отчёт не пришёл | расписание в UTC; `docker compose logs harness` |

## Что проверено, а что нет

Проверено локально: весь сценарий в одном процессе (`tests/test_demo_e2e.py`) с фейковыми DeepSeek и Telegram, отдельные цепочки — на запущенных процессах. 23.10 отдельно проверены настоящий DeepSeek через C-2 и рой на заявке 1042: модель нашла нехватку 4 шт., предложила A-17M, посчитала маржу 19,05 % (порог 15 %), критик подтвердил все утверждения; расход $0,0389. Не проверено: сборка стека в Docker, полный сценарий с настоящим DeepSeek и Telegram на VPS, вход через настоящий Telegram.
