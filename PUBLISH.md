# Публикация: публичный репозиторий + лендинг с дистрибутивами (T-36)

Для Сергея. Цель — поднять **публичный** репозиторий, на нём GitHub Pages со страницей установки и архивами релиза, по которым пользователь ставит MetaBrain одной командой. Текущий рабочий репозиторий `graycep1-spec/metabrain` **приватный и остаётся таким** — публичный это отдельный репозиторий с тем же кодом.

## Что уже готово (в этом репозитории)

- `install.sh` (Linux, macOS), `install.ps1` (Windows) — установка одной командой, повторный запуск = обновление.
- `get.sh` / `get.ps1` — загрузчики: скачать архив → сверить SHA-256 → запустить установщик. Адрес дистрибутивов в них — плейсхолдер `__METABRAIN_BASE__`, его подставляет CI при релизе.
- `docs/index.html` — страница лендинга (в командах `<страница>`/`<репозиторий>` — плейсхолдеры, CI подставляет реальные адреса).
- `.github/workflows/release.yml` — по тегу `v*` собирает архивы `tar.gz`/`zip`, `SHA256SUMS`, `latest.txt`, страницу → публикует на **GitHub Pages** и прикладывает архивы к **Release**.

## Что проверено

- **Секретов в истории нет** (прогон по всем коммитам 23.10.2026: committed `.env` нет, токенов/ключей нет; совпадения — регулярка детектора в `src/validator/checks/detectors.py` и фейковые строки в тестах DLP). **Но историю приватного репо публиковать всё равно НЕЛЬЗЯ:** в ней внутренние адреса стендов (`deploy/tsn/`, `STATE.md`) и рабочие заметки. Урок 23.10: `git push public main` утащил в публичный репо все 110 приватных коммитов, пришлось переписывать историю public заново.
- **В архив релиза секреты не попадают:** `git archive` берёт только закоммиченные файлы (`.env` в `.gitignore` и не коммитился), workflow дополнительно падает, если в архиве найдётся `.env`.
- Пайплайн релиза прогнан локально: архивы ~318 КБ / ~419 КБ, `SHA256SUMS` сходится, адреса подставляются.

## Шаги

Решение по владельцу принято (аккаунт Анны, имя `metabrain`, код открытый) — но публиковать может и твой аккаунт/организация. Ниже `<OWNER>` = аккаунт, где будет публичный репозиторий.

1. **Создать публичный репозиторий** `github.com/<OWNER>/metabrain`:
   ```bash
   gh auth login                                   # один раз, если ещё не залогинен
   gh repo create <OWNER>/metabrain --public --description "MetaBrain — фабрика цифровых сотрудников"
   ```
   (или вручную: github.com/new → имя `metabrain`, Public, без README/лицензии).

2. **Залить код снапшотом, БЕЗ приватной истории** (политика от 23.10.2026: в public —
   только локальная версия, инструкции и описание фич; весь контур веб-стенда — приватно):
   ```bash
   git remote add public https://github.com/<OWNER>/metabrain.git   # один раз
   git checkout --orphan public-root                 # дерево = main, истории нет
   git rm -rf deploy/tsn && git rm -f STATE.md       # внутреннее — не публикуем
   # вычистить упоминания стенда (ссылки на STATE.md, `.136`, имена серверов) из README,
   # deploy/README.md, DECISIONS.md, docs/СКИЛЛЫ.md — см. коммит 6e22e79 в public как образец
   git add -A
   git grep --cached -niE '<IP стенда>|<хостнеймы>|duckdns|<имя бота>|<id бота>' && echo "СТОП: нашлось" || true
   git commit -m "MetaBrain — открытая версия (снапшот)"
   git push public public-root:main --force-with-lease
   git checkout main && git branch -D public-root
   ```
   Никогда не `git push public main` и не merge приватной ветки в public — это публикует
   всю приватную историю.

3. **Включить Pages:** Settings → Pages → Build and deployment → Source = **GitHub Actions**. (Без этого шага `release.yml` не сможет опубликовать страницу.)

4. **Выпустить релиз** — тег запускает сборку:
   ```bash
   git tag v0.1.0
   git push public v0.1.0
   ```
   `release.yml` соберёт архивы, посчитает суммы, подставит адрес Pages в загрузчики и страницу, опубликует Pages и создаст Release.

5. **Проверить.** Через 1–2 минуты после деплоя:
   - страница: `https://<owner>.github.io/metabrain` (owner строчными);
   - установка с чистой Linux-машины с Docker: команда со страницы (`curl -fsSL …/get.sh | METABRAIN_BASE=… bash`) должна скачать, сверить сумму и поднять стек; `curl http://127.0.0.1:8081/healthz` отвечает;
   - подмена архива должна валить установку на несовпадении SHA-256.

## Если репозиторий у Анны

Анне нужно выполнить только шаг 1 (`gh auth login` в своём терминале) — дальше шаги 2–5 сделает Claude в её сессии: у неё локальная рабочая копия, после входа в `gh` создание репозитория, пуш, Pages и тег автоматизируются.

## Замечания

- `origin` (приватный `graycep1-spec/metabrain`) при этом не меняется: публичный — отдельный remote `public`.
- Лицензия уже GPL-3.0 (`LICENSE`), код открывается на этих условиях.
- **Политика публичного репо (Анна, 23.10.2026):** выкладывается только локальная
  версия для установки в своём контуре, инструкции и описание проекта/фич. Всё про
  боевой веб-стенд (`deploy/tsn/`, `STATE.md`, адреса `.136`, домены, имя бота) —
  только приватно. Ключи и токены не светить нигде: ни в public, ни в private —
  только env/stdin при деплое.
- Перед каждой публикацией: `git grep` по чек-листу из шага 2 на staged-дереве
  должен быть пуст.
- Хостинг и доступ к дистрибутивам — открытый вопрос OPEN-18; этот вариант (публичный GitHub + Pages) его закрывает, если команда согласна выкладывать публично.
