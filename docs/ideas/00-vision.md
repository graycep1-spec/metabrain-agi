# Видение: фабрика цифровых сотрудников и сервисов

## Одной фразой

**Бизнес формулирует задачу словами — система собирает, проверяет и выпускает
цифрового сотрудника или работающий сервис, а человек остаётся на гейтах и целях.**

Это не «ещё один чат-бот» и не «генератор кода». Это операционная модель:
спека → декомпозиция → сборка роем → сертификация валидатором → выпуск →
эксплуатация → обучение на траекториях.

## Проблема

Классическая цепочка «бизнес → тикет → аналитик → разработчик → согласования →
админ → ландшафт» теряет контекст на каждом звене, а изменение превращается в
очередь на недели. При этом:

- требования живут в презентациях и переписке, а не в проверяемом контракте;
- качество зависит от людей, а не от воспроизводимого пайплайна;
- агенты внедряются точечно, без изоляции, аудита и оценки;
- публичный и on-prem контуры строят как две разные системы.

## Решение

### Конвейер из шести шагов

У каждого шага есть вход, работа, выход и гейт:

1. **Спека** — задача на языке бизнеса; агенты уточняют её до формального
   контракта (цель, границы, критерии приёмки, интеграции).
2. **План** — декомпозиция: что собрать, какими ролями, какой тест-план.
3. **Рой** — роли `аналитик · разработчик · критик` работают с контрактами, а не
   с «вайбами» (в MetaBrain — [`src/workforce/swarm.py`](../../src/workforce/swarm.py), ADR-026).
4. **Сборка** — артефакты по стандарту: паспорт роли, действия, адаптеры, тесты.
5. **Сертификация** — валидатор проверяет и выдаёт подписанный ScoreCard; не прошёл —
   возврат по классу фейла, человек код не правит (C-4, ADR-008).
6. **Выпуск** — сотрудник активируется по согласию куратора, работает по расписанию
   и событиям, оставляет аудит.

Человек стоит только на двух гейтах: **приёмка спеки** и **приёмка выпуска**.

### Цифровой сотрудник — роль, а не бот

Цифровой сотрудник (C-6) — это роль с полномочиями, метриками и процессом. Он
работает в контуре платформы, действует через контракты, оставляет аудит и
прикрепляется к целям (проектам, процессам — ADR-032). У каждого человека — свой
харнесс; компания — тенант (ADR-002).

Внутри один сотрудник — это рой (аналитик/разработчик/критик) с одним голосом
наружу. Служебный Исследователь строит карту ландшафта и черновики адаптеров.

### Мета-мозг: система учится на себе

- **телеметрия** каждого шага (append-only, с редактированием PII и секретов);
- **валидатор** проверяет схему, причинность, grounding, политику, исход и replay,
  а LLM-судья — только advisory (C-4, ADR-016);
- **дистиллят** превращает проверенный опыт в переиспользуемый сигнал;
- **мета-мозг** (C-5) хранит навыки и playbooks и **предлагает** действия, но
  применяет их только через гейт куратора (ADR-029, C-006);
- **самосовершенствование** политик идёт ступенями `shadow → canary → stable`
  с откатом — см. [03-meta-brain-self-improvement.md](03-meta-brain-self-improvement.md).

### Автономия — ступенями, не «прокачкой модели»

Автономия растёт зонами через политики: больше систем, шире права, больше доверия
по итогам гейтов. В целевом MVP — ступени L0–L2 (ADR-006, ADR-011). Подробнее —
[04-autonomy-hierarchy.md](04-autonomy-hierarchy.md).

## Два контура, один каркас

| | Public | On-prem |
|---|---|---|
| Где | Один слабый VPS, контейнеры | Контур заказчика |
| Модели | Внешний OpenAI-совместимый API | Локальный inference, без выхода наружу |
| Данные | Демо/публичные | Данные заказчика, изоляция |
| Секреты | `.env`, не в git; vault для доступов из кабинета | Secret manager / env |

Каркас один. Отличаются адаптеры (LLM — C-2, интеграции — C-3) и профиль
развёртывания. Провайдера и модель можно переключить из кабинета (ADR-033).
Фича, которая требует «другой системы» для on-prem, считается недоделанной.

## Что считается успехом

- **Скорость**: задача → работающий сотрудник/сервис — дни, не кварталы.
- **Качество**: доля артефактов, прошедших валидатор с первой итерации.
- **Доверие**: 100% действий агентов с аудитом; PII и секреты не утекают.
- **Автономия**: доля задач, закрытых без человека, растёт по ступеням.

## Границы

- Фабрика не «пишет код без контроля»: она проходит гейты и валидатор.
- Агент не получает «весь ландшафт»: только точечные права по политикам.
- Публичный каркас не содержит внутренних имён, адресов и секретов.
