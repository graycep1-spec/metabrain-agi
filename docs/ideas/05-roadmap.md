# Дорожная карта

Статусы отражают текущую реализацию MetaBrain. Детали — в
[`specs/50-tasks.md`](../../specs/50-tasks.md) и [`DECISIONS.md`](../../DECISIONS.md).

## Реализовано

- **Харнесс на человека, компания — тенант** (ADR-002); изоляция данных на уровне
  хранилища.
- **Цифровой сотрудник = роль** (C-6): паспорт, память, уровни автономии; активация
  по согласию (ADR-024).
- **Рой** аналитик · разработчик · критик (ADR-026); служебный Исследователь (ADR-004, ADR-023).
- **Валидатор** с профилями и подписанным ScoreCard, fail-closed (C-4, ADR-016, ADR-008).
- **Мета-мозг**: навыки личные/компании, полнотекстовый ретривал, политика-файл,
  MCP-сервер со scope (C-5, ADR-018, ADR-022).
- **Согласия и гейты куратора** (C-006, ADR-008); инвайт в компанию (ADR-010),
  саморегистрация и присоединение по коду в кабинете (ADR-030).
- **Процессы · проекты · прикрепления · задачи** в харнессе (ADR-032).
- **Автономия L0–L2** (ADR-006, ADR-011).
- **Безопасность доступов**: env secret store (ADR-014), vault-lite для доступов из
  кабинета (ADR-028), DLP перед внешним LLM.
- **LLM**: коннектор и роутер (C-2), бюджеты по факту (ADR-021), настройка
  провайдера/модели/ключа из кабинета (ADR-033).
- **Каналы**: Telegram (ADR-007), веб-кабинет управления (ADR-012, ADR-025).
- **Поставка**: один VPS, Docker Compose, профили public/on-prem, установщик.

## Планируется (ближний горизонт)

- **Телеметрия → проверки V1–V7 → дистиллят** как единый контур
  ([02-telemetry-validator.md](02-telemetry-validator.md)).
- **Самосовершенствование** мета-мозга: траектории → playbooks → действия →
  политики `shadow → canary → stable`, всё через гейт (T-37, ADR-029,
  [03-meta-brain-self-improvement.md](03-meta-brain-self-improvement.md)).
- **Автономия A3/A4** (достраивание недостающего, трансформации) за пределами
  демо-среза.
- **Мультиканальность**: адаптеры каналов помимо Telegram.

## Ресурсная модель AI-нагрузок (roadmap)

Сейчас мощность управляется бюджетами (ADR-021). Целевая модель — AI-нагрузки
(inference, agent runtime, MCP-эндпоинты) как ресурсы платформы:

- **Слот** — единица AI-мощности: токены/сек, параллелизм сессий, GPU-время.
- **Квоты**: гарантированный минимум + burst по спросу + приоритеты.
- **Биллинг** по факту: токен / вызов / секунда; scale-to-zero; chargeback.
- **MCP как FaaS**: MCP-эндпоинты и agent-runtime как функции.
- **Модельный роутинг**: open-source ↔ коммерческие, cost/latency, failover;
  тёплые пулы для частых моделей.

Границы: не строим «ещё один роутер» — платформа владеет ресурсно-сервисной
моделью AI-нагрузок, а движок маршрутизации остаётся отдельным.

## Уроки (из опыта, чтобы не повторять)

- **Видимость заказа**: создатель должен видеть свой заказ даже в общем проекте —
  иначе UI-тупик. Не понижать `target_project` молча: fail-closed или явная метка.
- **Форма следует вкладке**: не дублировать поля «сотрудник/идея» в каждой вкладке.
- **Спецификация — в карточке**, а не только в модалке гейта.
- **Проверка прав на роутах прикреплений обязательна**: нельзя по id чужого заказа.
- **Проверки запускать на правильной среде**: liveness/TDD — против выпущенного
  экземпляра, а не локально.
- **CRLF и кодировки**: следить на кроссплатформенной сборке (исторические гочи).
